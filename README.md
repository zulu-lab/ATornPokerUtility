ATornPokerUtility – Terms of Service

Overview

ATornPokerUtility is a client-side userscript designed to enhance the poker experience on Torn.com by collecting gameplay data and providing real-time statistical insights via a HUD.

This document explains:
	•	What data is collected
	•	What data is sent to the server
	•	What data is received
	•	How the system is secured
	•	Why a Torn API key is required
	•	How data is stored

By using this tool, you agree to these terms.

⸻

Data Collected and Sent

The script collects only gameplay-related data visible in the Torn poker interface.

Player Data
	•	Torn Player ID
	•	Player Name (as displayed in-game)

Table & Session Data
	•	Table ID
	•	Session ID (generated by the server)
	•	Hand identifiers (when available)

Gameplay Events

The script observes and sends structured poker events such as:

Base events:
	•	join, leave
	•	fold, call, raise, bet, check, all-in
	•	call_preflop, raise_preflop

Advanced events:
	•	hand_dealt
	•	saw_flop
	•	showdown, win_showdown
	•	3bet, fold_to_3bet
	•	cbet_flop, fold_to_cbet
	•	squeeze, donk_bet, check_raise
	•	fold_bb_to_steal, faced_steal_bb

Contextual Metadata

Each event may include additional contextual information:
	•	street (preflop / flop / turn / river)
	•	action_index (order of actions)
	•	is_aggressor (true/false)
	•	hand_result (win / lose / fold)
	•	seat position
	•	raw in-game status
	•	previous status
	•	raw event type
	•	board cards (community cards)
	•	players snapshot (lightweight table state)

If data is not available, it is sent as null.
No data is artificially generated.

Stack & Betting Data
	•	Stack before action
	•	Stack after action
	•	Bet / call amounts (when available)

⸻

Data Received from the Server

The script retrieves aggregated statistics computed server-side:
	•	Hands played
	•	VPIP
	•	PFR
	•	Aggression Factor (AF)
	•	3-bet %
	•	Fold-to-3-bet %
	•	C-bet (flop) %
	•	Fold-to-C-bet %
	•	Limp %
	•	Squeeze %
	•	Donk bet %
	•	Check-raise %
	•	WTSD (Went to Showdown)
	•	WSD (Won at Showdown)
	•	Fold BB to steal

These statistics are derived from accumulated gameplay data.

Why a Torn API Key is Required

The API key is used only to:
	•	Retrieve your Torn Player ID
	•	Authenticate you with the server
	•	Associate gameplay data with a valid user

Important
	•	The API key is used locally by the script
	•	Only minimal endpoints (basic user data) are accessed
	•	No private or sensitive Torn data is collected

⸻

Security Model

The system uses a layered approach:

Token-Based Authentication
	•	The server issues a session token after validation
	•	All requests use this token
	•	Unauthorized requests are rejected

Controlled Execution
	•	The script only runs when the page is active
	•	No background data transmission
	•	No data is sent when the page is unfocused

Data Scope Limitation

The system does NOT collect:
	•	Passwords
	•	Financial information
	•	Private messages
	•	Any non-gameplay personal data

⸻

Data Storage

All transmitted data:
	•	Is stored on the server
	•	Is used to compute statistics
	•	May be retained permanently

To maintain performance:
	•	Raw event data may be periodically purged
	•	Aggregated statistics may persist long-term
